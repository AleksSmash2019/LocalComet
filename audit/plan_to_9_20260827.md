# LocalComet — blockers и план достижения честной оценки 9/10

**Дата:** 2026-08-27  
**Основание:** текущий coder report, baseline/gate artifacts и acceptance matrix мастер-промпта.  
**Текущий статус:** `PENDING_TERMINAL`, честная оценка **7.8/10**.  
**Целевая формулировка:** не «сделать красивее», а получить текущие, воспроизводимые evidence класса A там, где acceptance matrix требует независимую проверку.

> Прохождение unit/contract gates доказывает корректность соответствующего source seam, но не доказывает native Computer Use, process ownership, URL/title, UIA, restart или cleanup. Исторический успешный прогон не является доказательством текущего состояния.

## 1. Краткий вывод

Сейчас LocalComet имеет сильный contract baseline: frontend проверен как `0 errors / 0 warnings`, Vitest показывает 552 passed, Rust — 731 passed / 0 failed / 7 ignored, а Python pack и real-sidecar gate завершились с exit code 0. Эти факты подтверждены текущим tree digest `08c0ff94e3c7a6fa478e4fd8b9d90237d786f3950711a72c72364a0c16c94563` для 588 source files [R1].

Оценка не поднимается выше 7.8 не из-за текущего количества тестов, а потому что не закрыты **execution-based acceptance gaps**. Главные из них: отсутствует свежая native matrix с exact ownership и независимыми postconditions; нет current process-boundary restart proof; approval-modal путь не подтверждён native correlation evidence; полный hostile corpus не запускался; Project Intelligence v2 пока не подключён к production command/control-plane path; не измерены performance metrics; не завершён provenance/legal decision ledger.

Достижение **9.0/10** следует трактовать как release-candidate milestone, а не как арифметический бонус за добавленные тесты. Для него необходимо закрыть все критические execution seams текущим evidence-пакетом и не иметь открытого P0 false-positive acceptance defect. Порог **9.5** из мастер-промпта остаётся более строгим: его нельзя заявлять без закрытия всех P0 rows независимыми доказательствами.

## 4. Детальный план закрытия blockers

### Фаза 0 — разблокировать безопасную native среду

Сначала не нужно менять код. Нужно получить чистое owner-scoped execution window. Новый run создаёт уникальные isolated roots, hidden desktop, browser profile, fixture и report directory; в manifest заранее перечисляются owned paths и roots. Перед запуском фиксируется process table и проверяются Vite/CDP ports. После запуска проверяются launcher PID, native child PID, descendant tree и creation identity.

Исторические Chrome/WebView2 процессы нельзя закрывать по image name. Если они принадлежат предыдущему harness run, cleanup допускается только через exact manifest/job owner tree; если ownership не доказан, процесс остаётся нетронутым, а native run получает `VERIFIED_BLOCKED` или `NOT_INDEPENDENTLY_VERIFIED`, не optimistic success.

**Exit criteria:** нет активного LocalComet-owned/previous-run resource, который конфликтует с isolated run; report содержит baseline process guard, owner manifest, exact ports, source/tree digest и cleanup policy.

### Фаза 1 — довести сквозной typed contract и approval authority

Нужно провести audit существующих `agent turn`, control-plane, approval, tool-result и evidence envelopes, а не создавать параллельный формат. На Rust boundary должны быть валидированы task/session/workspace/model/action/input digest, risk, approval reference, bounded payload и exact verdict vocabulary. Python и frontend получают уже typed authoritative state; они не могут повышать risk, выдавать grant или объявлять success.

Для approval необходимо разделить два пути. **Authoritative path** — Rust `request_tool_approval` event с server-issued request ID, model IDs и canonical input digest, который отображается в modal и точно передаётся в `resolve_tool_approval`. **Legacy compatibility path** — только диагностическая/совместимая карточка без права выдавать native approval evidence. Нужны component tests на реальный DOM и negative test на чужой request/digest.

**Exit criteria:** schema/parity tests зелёные; unknown/oversized/mismatched fields fail closed; native harness умеет выбрать только exact correlated approval control; compatibility card не может быть классифицирована как authoritative approval.

### Фаза 2 — production wiring Project Intelligence v2

`project_intelligence.rs` следует подключить к существующему Rust-owned context/control-plane seam минимальным read-only command без расширения authority. Предлагаемое имя команды — `context_manifest_build`; если существующий command уже выполняет эту роль, нужно расширить именно его, а не добавлять дубликат.

Команда принимает только bounded typed request: confirmed workspace identity, task ID, optional step ID, task keywords, explicit user files и byte budget. Workspace path не должен приниматься как свободный arbitrary path без текущей Rust workspace validation. Внутри вызывается fallible API, а отказ по invalid budget, unreadable root, symlink/reparse или context overflow возвращается typed error. Manifest должен содержать `inventory_digest`, `content_digest`, `context_manifest_hash`, generation и provenance; секреты и build artifacts должны отбрасываться до model context.

Нужно добавить command parity, Rust negative tests, deterministic same-tree/same-task test, one-file digest-change test, secret/build/symlink/traversal tests и cross-layer serialization test. Compatibility wrapper можно сохранить для старых unit callers, но production path не должен использовать panic-based API.

**Exit criteria:** command registered and invoked, parity gate green, identical tree/task produces identical manifest hash, one file change changes content/context digest, oversized context returns bounded typed error, production context consumer references exact manifest hash/provenance.

### Фаза 3 — current native matrix

Запускать cases только по одному. Для каждого case сохраняются `case_id`, request/action/call IDs, approval hash, workspace digest, exact process identity, fresh observation, independent postcondition, cleanup result и exact verdict. Harness должен использовать current source/tree digest, а не старый binary/evidence.

| Case | Независимое postcondition | Минимум для `VERIFIED_SUCCESS` |
|---|---|---|
| Notepad open/type | Exact synthetic marker прочитан независимым UIA/native read-only probe; marker SHA; owned close; zero leftovers | PID/desktop/creation identity + fresh UIA readback + cleanup |
| Browser readonly search | Exact owned browser PID/profile/CDP target, allowlisted HTTPS URL, non-empty title, expected host/query semantics, owned close | PID/profile/CDP/URL/title all correlated |
| Fixture files | Canonical fixture root, no traversal/reparse, exact before/after bytes and SHA, owned cleanup | Disk bytes/hash postcondition, not UI claim |
| Screenshot/observe | Fresh screenshot tied to exact process/desktop/action, backend/scope/bytes/SHA | Fresh capture metadata and correlation |
| Cancel/timeout | No mutation or proven rollback/safe cleanup; no stale continuation | Cancellation-to-safe-state evidence |
| Foreign ownership | Matching title/wrong PID left untouched | Ownership mismatch blocked before action |
| Approval | Exact modal control for current request/digest; no generic approve click | Correlated request/action/input data plus decision evidence |

For the key Notepad, browser, fixture-files and screenshot scenarios нужно получить **две свежие повторы** на одном current source tree, не считать их двумя разными historical artifacts. Каждая повтор должна иметь отдельный report dir и cleanup proof.

**Exit criteria:** all required cases have per-case JSONL; no row becomes green from image name, stale screenshot, UI pill or self-report; infrastructure/startup failure is separated from tool/action failure.

### Фаза 4 — restart and recovery

Создать отдельный test task, который доходит до state where host action is pending. После этого завершить приложение только через exact owner-scoped process boundary, не используя user process kill. При повторном открытии проверить snapshot hash, event chain, current workspace digest, model binding, checkpoint state и pending action.

Ожидаемое поведение: non-terminal task становится `paused_for_review` или equivalent; ни один host mutation не replay-ится; старый grant не принимается; recovery view read-only. После нового user action создаётся новый `execution_attempt_id`, новый correlation chain и новое exact approval на следующий action. Если snapshot/event chain corrupt, task остаётся видимым как `corrupt` и continuation запрещён.

**Exit criteria:** restart case имеет before/after filesystem/process evidence, zero-replay assertion, new attempt ID, rejection of old grant и evidence ref на read-only recovery.

### Фаза 5 — hostile security matrix

SEC-001…SEC-016 следует проводить как отдельные fixtures с protected postcondition. Важно проверять не только текст warning, но и то, что secret не ушёл, файл не изменился, чужое окно не тронуто, navigation не произошла, grant не consumed, а последующие ordered actions не dispatch-ились.

| Группа | Cases | Protected postcondition |
|---|---|---|
| Untrusted content / injection | SEC-001, SEC-002, SEC-010 | Нет upload/escalation/permission change; принимается только exact Rust-correlated control |
| Path/filesystem | SEC-003, SEC-004 | Нет filesystem I/O до reject; reparse/symlink/traversal fail closed |
| Process/command/navigation | SEC-005, SEC-006, SEC-011 | Нет arbitrary process/command/navigation; wrong PID/title остаётся untouched |
| Grants/ledger/resources | SEC-007, SEC-008, SEC-009, SEC-016 | Binding mismatch/corrupt interior/oversize/restart replay rejected boundedly |
| Ordered execution / packages | SEC-012, SEC-013, SEC-014 | Later actions not dispatched; archive quarantined; tampered skill disabled |
| Auth handoff | SEC-015 | Typed block or explicit handoff, no headless hang |

**Exit criteria:** 16 rows имеют input, expected, actual, evidence ref, mutation check и exact verdict. Contract-only rows помечены как contract-only, если native protected postcondition не выполнялось.

### Фаза 6 — measurements и provenance

Измерения делаются только после стабилизации harness. Каждый metric report обязан содержать environment, source/tree digest, `n`, p50, p95, max и failures. Если кейс блокирован, это пишется как `NOT_MEASURED` с причиной, а не заменяется историческим числом.

Provenance inventory ведётся отдельно от native evidence. Для каждой зависимости/модели/голоса/skill/test artifact указывается local SHA и source URL, а unresolved license/redistribution/commercial questions переходят в `owner_decision_required`. Нельзя добавлять root `LICENSE` или заявлять legal clearance без решения владельца.

**Exit criteria:** performance JSON и provenance inventory связаны с current source/evidence tree; release blockers перечислены явно; raw tokens, cookies, API keys и пользовательские файлы отсутствуют.

### Фаза 7 — финальный acceptance pack

После последней существенной правки заново запускать полный frontend, Rust, Python, real-sidecar, evidence refresh/provenance и parity gates. Затем обновлять dashboard только verified facts. Исторические reports не удалять, checkpoint не обнулять, score не повышать до тех пор, пока текущий pack не содержит все необходимые evidence refs.

**Exit criteria:** один финальный report с branch/HEAD/status, changed files, exact gate commands/exit codes/last lines, native matrix, SEC matrix, performance/provenance, remaining items и score caps. Dashboard не должен использовать optimistic `PASS`, если independent postcondition отсутствует.

## 5. Зависимости и критический путь

```text
clean owner-scoped environment
        ↓
exact PID/CDP/UIA harness proof
        ↓
approval modal + semantic browser/files/screenshot proof
        ↓
restart/recovery no-replay proof
        ↓
hostile SEC matrix
        ↓
performance + provenance
        ↓
full fresh gates + independent report
        ↓
9.0 release-candidate decision
```

Project Intelligence production wiring и typed contract audit можно выполнять до native run, однако их acceptance всё равно должен попасть в тот же current source/tree digest. Performance нельзя финализировать до того, как native harness перестал давать false positives и infrastructure failures.

## 6. Критерии достижения 9.0

Это не формальная арифметическая формула, а минимальный набор условий, который устраняет текущие score caps.

| Acceptance row | Условие для 9.0 candidate |
|---|---|
| Agent loop | Typed plan/action/observation/result, bounded iterations, cancellation и terminal state подтверждены current contract + relevant execution proof |
| Coding IDE | Exact approval, checkpoint, compile-only distinction, behavior proof и rollback имеют current evidence |
| Context | Project Intelligence production command использует hard budget, secret-safe deterministic manifest и provenance |
| Skills | Quarantine/checksum/disabled third-party/workflow allowlist/postcondition закрыты contract + hostile fixtures |
| Persistence | Hash chain/snapshot/corrupt fail-closed/workspace binding/restart read-only recovery закрыты, включая process boundary |
| Model | Exact artifact/provenance/SHA/GGUF, correlated health, capabilities и fallback state подтверждены текущим run |
| Native CU | Notepad, browser, files, screenshot, cancel/timeout и foreign ownership имеют independent A evidence; ключевые cases повторены |
| Approval UX | Native modal correlation exact; compatibility card не может выдать authority |
| Security | SEC-001…SEC-016 имеют защищённые postconditions и корректные verdicts |
| Release | Fresh full gates, parity, performance report, provenance/legal blocker ledger и non-contradictory status report |

Если хотя бы один P0 native/recovery/security row остаётся только source evidence, score должен оставаться ниже 9.0 либо помечаться как `NOT_INDEPENDENTLY_VERIFIED`. **9.5 не заявлять**, пока не выполнены все P0 rows именно в требуемом независимом смысле.

## 7. Первые три действия после разблокировки среды

1. Зафиксировать чистое owner-scoped execution window и проверить, что новый harness не пересекается с историческими hidden Chrome/WebView2 processes. Не закрывать процессы по имени.
2. Закрыть typed approval/legacy-card seam и production wiring Project Intelligence через существующий Rust-owned command path, после чего повторить targeted Rust/Python/frontend tests.
3. Выполнить два current-source Notepad runs, затем по одному browser/files/screenshot run; только после этого переходить к restart и hostile matrix.

## 8. Что не следует делать

Нельзя повышать score на основании только зелёных unit tests, количества тестов, UI readiness pill, model-ready label, открытого порта, лога или одной ручной демонстрации. Нельзя заменять Qwen/model/runtime silently, расширять risk registry новыми уровнями, передавать authority во frontend/Python, использовать user Chrome/profile, запускать Calculator hidden/automatic mode или делать broad process cleanup. Нельзя удалять historical evidence, dirty WIP, checkpoint или timeline records только ради красивого статуса.
