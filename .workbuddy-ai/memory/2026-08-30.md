### Нестабильность запуска моделей — 7 подтверждённых причин

Все по `desktop/localcomet-desktop/src-tauri/src/managed_runtime.rs`.

1. **Нет retry и деградации.** grep `retry|reattempt|degrade` → 0 совпадений.
   `fallback_runtime_ids` — только поле `ManagedRuntimeCapability` (default `Vec::new()`,
   заполняется в тестах), на запуск не влияет.
2. **Жёсткий таймаут, которого у LM Studio нет.** `MODEL_LOAD_TIMEOUT = 600s`,
   динамический `180 + (10.0 * model_size_gb)` с `.min(600)` (строка 744).
   8 ГБ → 260 с, 24 ГБ → 420 с. «Медленно» превращается в «не запустилось».
3. **Консервативный RAM-guard** (757–769): `available_ram_gb < model_size_gb + 0.5`
   → `model_does_not_fit`; обходится только при partial GPU offload. llama.cpp
   mmap'ит, реальный RSS ниже размера файла → отказ там, где модель бы влезла.
4. **Минимальный набор флагов.** Всего 18 строк-флагов в файле, 4 из них пробы
   (`--help --version --list-devices`). Стартовые: `--model --mmproj --host --port
   --api-key-file --no-webui --no-agent --jinja --reasoning-format --fit --fit-ctx
   --ctx-size --gpu-layers --n-predict --alias`. **Отсутствуют** `--threads/-t`,
   `--batch-size/-b`, `--ubatch-size/-ub`, `--flash-attn`, `--mlock`, `--parallel/-np`,
   `--cache-type-k`, `--cache-type-v`. llama.cpp берёт свои дефолты
   (threads = hardware_concurrency incl. SMT → oversubscription; batch 2048 → пик VRAM).
5. **Дефолтный контекст 2048.** `auto_gpu_fit = accelerated && gpu_layers_override.is_none()`,
   `auto_context_fit = auto_gpu_fit && ctx_size_override.is_none()` → `--fit on
   --fit-ctx 2048`. Собственная RAM-эвристика (8192/4096/2048) достигается только
   в `else`-ветках, т.е. на CPU-пути.
6. **Ошибки непрозрачны.** Три разных сбоя дают один `launch_failed`:
   `ContainedManagedRuntimeProcess::spawn()` — `Err(_)` на строке 807, **OS-ошибка
   отброшена**; ридер stdout; ридер stderr («log reader could not start»).
   `wait_ready()` → `runtime_exited` «exited before readiness» (строка 1861) **без
   exit code**. `ManagedRuntimeStatus` (81–96) имеет только `last_error: Option<String>`,
   поля exit code нет вообще.
7. **UI не предлагает retry.** `RETRYABLE_CODES` в
   `desktop/.../src/lib/errors/normalizedError.ts:27` = `{sidecar_unavailable,
   bridge_unavailable, stream_timeout, readiness_timeout, model_stream_timeout}`.
   Нет `launch_failed`, `runtime_exited`, `model_does_not_fit`. i18n-ключей для них тоже нет.

**Что работает правильно** (проверено, чтобы не валить всё подряд): stderr/stdout
сливаются живьём в отдельном потоке `spawn_log_reader` (2466) с редактированием
секретов в кольцевой буфер 256 КиБ → `managed_runtime_logs` → `modelGateway.ts:321`
→ `stores/modelGateway.ts:650` → рендер в `ManagedRuntimePanel.svelte:107-108` и
`ObservabilityRoom.svelte:75-76`. Байты есть, но **не привязаны к ошибке**.
Блокировки пайпа на 64 КиБ нет (читатель есть) — эта гипотеза снята.
Job Object, loopback `127.0.0.1`, api-key-file, 13-ключевый env-allowlist — в порядке.
