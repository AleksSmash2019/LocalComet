==================================================
1. РЕЖИМ РАБОТЫ
==================================================

MAX_CONCURRENT_SESSIONS=2

Session 1:
- validation/build owner;
- единственный процесс, создающий build artifacts;
- не меняет source code во время первичной проверки.

Session 2:
- independent read-only judge;
- проверяет exact frozen HEAD;
- не чинит и не коммитит;
- повторяет ключевые gates независимо.

Запрещено:
- push, rebase, reset --hard, history rewrite;
- изменение accepted branch;
- два writer;
- чтение или печать `LocalComet MCP Bearer Token.py`;
- вывод токенов, grants, nonces, credentials;
- ослабление tests/contracts ради PASS;
- включение tool execution без explicit authority;
- destructive tests на пользовательских данных;
- использование stale build outputs как доказательства.

==================================================
6. ЧИСТАЯ RELEASE BUILD
==================================================

После успешных gates:
- удалить только build artifacts внутри изолированной среды;
- сохранить source untouched;
- проверить lockfiles;
- найти реальную release command в package scripts, Tauri config, CI или docs;
- не угадывать команду;
- выполнить clean release build.

Сборка должна:
- exit 0;
- создать current artifacts;
- не использовать stale output;
- не включать debug/test secrets;
- не менять accepted source tree.

Для каждого artifact зафиксировать:
- exact build command;
- duration;
- path;
- size;
- SHA-256;
- architecture;
- file/product version;
- Authenticode status;
- bundle/installer type;
- exact HEAD;
- build log.

PowerShell:
Get-FileHash -Algorithm SHA256 <artifact>
Get-AuthenticodeSignature <artifact>
Get-Item <artifact> | Format-List *

Если проект создаёт MSI/NSIS/bundle — проверить каждый.
Если только EXE — указать честно.
Unsigned artifact не считать defect, если signing не входит в authority;
указать release limitation.

При наличии Windows Defender:
- выполнить безопасное локальное сканирование artifact;
- не отключать защиту;
- не добавлять exclusions;
- не загружать private artifact на публичные сервисы без approval.


==================================================
7. REAL WEBVIEW SMOKE — ОБЯЗАТЕЛЬНЫЙ RELEASE GATE
==================================================

`ENVIRONMENT_LIMITATION_DOCUMENTED` недостаточно для release-ready PASS.

Определи:
- installed Edge version;
- WebView2 runtime version;
- official Tauri-supported WebDriver tooling;
- compatible driver version;
- driver path;
- official source;
- checksum/license;
- test-only nature.

Не доверяй старой жёстко указанной версии без проверки среды.
Не устанавливай непроверенный package.
Не добавляй production dependency.

Используй `tests/webview-smoke.mjs` или актуальный repository-authorized entrypoint.

Smoke обязан реально проверить:
1. app launch;
2. first meaningful render;
3. no blank/white screen;
4. no fatal frontend/runtime error;
5. no fatal console error;
6. one safe IPC round trip;
7. one reachable dialog/modal;
8. keyboard close;
9. correct focus return;
10. clean shutdown;
11. no orphan processes;
12. no tool execution side effect.

Зафиксируй:
- command;
- Edge/WebView2/driver versions;
- artifact SHA-256;
- exact HEAD;
- duration;
- console/runtime logs;
- exit code;
- orphan process check.

Если нужен system-wide install, admin, license acceptance или unverified
external download — HARD HUMAN DECISION.

Без реально выполненного WebView smoke RELEASE_GATE_PASS запрещён.


==================================================
8. РУЧНАЯ СЦЕНАРНАЯ ПРОВЕРКА
==================================================

Запускай собранный artifact, не dev server.

A. Startup
- первый и повторный запуск;
- два быстрых запуска;
- clean shutdown и forced close;
- no blank screen/infinite spinner;
- correct title/version;
- понятная безопасная ошибка.

B. Local endpoint
- local-only notice;
- localhost success/failure;
- remote endpoint не обещается;
- Retry Connection только повторяет health check;
- no config mutation;
- no hidden runtime start;
- no fake connected;
- stale health result не перезаписывает новый state.

C. Messages
- 1,2,3,4 accepted;
- 5 rejected;
- exact UTF-8 boundary;
- one byte over;
- emoji/CJK;
- frontend/backend parity;
- no hidden `*2`.

D. Acquisition
- transient retry 1s и 2s;
- exhaustion → manual Retry;
- 4xx no retry;
- cancel no retry;
- digest/security/filesystem terminal;
- no fake percentage;
- no duplicate acquisition.

E. Async stale protection
- overlapping requests;
- reverse completion;
- changed fingerprint;
- cancellation;
- old workspace/session result;
- stale result no mutation;
- no auto-rebind.

F. Dialogs/accessibility
- Tab/Shift+Tab;
- initial focus;
- focus trap/return;
- Escape;
- accessible name/description;
- error/status announcement;
- destructive warning;
- high contrast;
- reduced motion;
- no keyboard trap.

G. Frontend events
- valid event;
- unknown top-level/nested rejected;
- missing rejected;
- null vs missing;
- duplicate key;
- invalid enum/type;
- malformed envelope;
- no crash/fake success.

H. Approval/security
- renderer not approval authority;
- ApprovalCard presentation-only;
- rejection blocks action;
- stale/reused/mismatched grant rejected;
- no token/grant/digest in UI/log;
- tools remain disabled per authority.

I. Restart/state
- no stale transient state;
- no stale approval;
- no duplicate dispatch;
- no orphan process;
- no corrupt state after forced close;
- missing/corrupt optional config fails safely.

J. Filesystem/workspace
- normal, spaced and Unicode paths;
- read-only/missing path;
- simulated symlink/junction/reparse escape in disposable temp workspace;
- no write outside workspace;
- no user-data destructive tests.


==================================================
9. LOGGING, STABILITY И CLEAN-MACHINE
==================================================

После success и всех основных failures проверь logs на отсутствие:
- bearer/API keys;
- approval tokens;
- grants/nonces;
- credentials/private keys;
- forbidden full digests;
- unnecessary private paths;
- raw sensitive user content.

Проверь:
- errors truthful;
- terminal failure не маскируется;
- correlation context достаточен;
- authority-bearing values не восстанавливаются из logs.

Stability:
- 10 launch/close cycles;
- 20 dialog open/close cycles;
- 10 Retry Connection cycles;
- 10 invalid event injections в test harness;
- 5 cancel/retry acquisition cycles.

Измерить без выдуманных thresholds:
- cold/warm startup;
- idle CPU/memory;
- memory growth;
- child/orphan processes;
- shutdown time;
- crashes/hangs/UI freezes.

Если доступна Windows Sandbox/VM:
- перенести только artifacts и documented prerequisites;
- не переносить repository/node_modules/target;
- startup + endpoint + dialog + shutdown;
- проверить отсутствие зависимости от developer machine paths.

Если недоступна:
CLEAN_MACHINE_TEST=NOT_RUN_ENVIRONMENT_LIMITATION
и применить repository authority к verdict.


==================================================
10. REPAIR POLICY
==================================================

Первичная validation — без source changes.

При defect:
1. зафиксировать failing HEAD;
2. создать evidence-backed finding;
3. сохранить logs;
4. вернуть первичный FAIL;
5. создать отдельный repair branch/worktree;
6. smallest safe fix;
7. regression test;
8. focused tests;
9. full regression;
10. clean rebuild;
11. повторный WebView/manual scenario;
12. independent audit нового exact HEAD.

Максимум 2 repair cycles:
BLOCKED_REPAIR_LIMIT

Не чинить ослаблением test, contract или validation.

==================================================
12. VERDICT RULES И ОТЧЁТ
==================================================

RELEASE_GATE_PASS только если:
- exact HEAD frozen;
- source clean;
- all required automated gates pass;
- clean build pass;
- artifact current and hashed;
- real WebView smoke pass;
- required manual scenarios pass;
- no unresolved CRITICAL/HIGH;
- no fake state;
- no secret leakage;
- independent judge pass;
- vault/evidence updated;
- PUSHED=false.

RELEASE_GATE_CONDITIONAL:
- нет CRITICAL/HIGH;
- limitation не является обязательным release gate;
- limitation точно документирована.

WebView limitation не допускает release-ready PASS.

RELEASE_GATE_FAIL если:
- build/test/WebView fail или not run;
- source/evidence mismatch;
- artifact не привязан к exact HEAD;
- CRITICAL/HIGH defect;
- security boundary weakened;
- fake state;
- secret leakage;
- unexpected source mutation;
- judge FAIL.

Финальный отчёт:
1. Executive summary
2. Exact HEAD/branch
3. Git/worktrees
4. Environment/toolchain
5. Source provenance
6. Automated gates
7. Test blind spots
8. Clean build
9. Artifact inventory + SHA-256
10. Signature/security scan
11. WebView smoke
12. Manual scenario matrix
13. Accessibility
14. Logs/privacy
15. Stability/resources
16. Clean-machine
17. Findings
